# 03 · 实时编辑与合并语义

## 1. 四条独立状态线

录音状态为 idle、starting、recording、paused、stopping、stopped、error。推理状态为 unloaded、loading、ready、running、catching_up、error。视图状态为 following、reading_history。编辑状态为 closed、drafting、saving、saved、save_failed。四条状态线分别建模，禁止用一个 `isPaused` 控制全部工作。

同一时刻允许录音为 recording、推理为 catching_up、视图为 reading_history、编辑为 drafting。编辑期间录音采集、音频落盘和推理调度继续工作。

## 2. 数据层次

| 层 | 内容 | 写入者 |
|---|---|---|
| 音频事实 | 采样位置、音频块、来源、缺口 | 录音服务 |
| 机器版本 | 同一转写块的完整识别快照、递增版本 | 推理适配器 |
| 人工修订 | 基准机器版本、用户文本、父修订、提交者 | 用户动作 |
| 课堂资料 | 图片、公式、例子、备注、稳定锚点 | 用户动作 |
| 展示投影 | 安全合并结果、冲突标记、段落分组 | 纯计算逻辑 |

展示层可重新计算。机器历史和人工修订历史分别保存。修改页面上展示的一个字符串无法替代这些记录。

## 3. 稳定的转写单位

每个 `segment_id` 对应采集运行中的一段有所有权的音频区间。其开始采样位置建立后保持固定，结束位置在识别过程中可单调增长，最终确认后冻结。标点、句子切分与视觉段落属于派生展示，后续模型变化保持原 ID。

首版按语音活动检测和最大长度生成短块，并允许一个块包含多个短句。用户点“取出编辑”时得到这个固定音频块。未来需要句级选择时，可以在固定块内添加选择范围，避免依赖持续漂移的句子序号。

跨块合并与拆分留到独立操作：保留原块、建立派生组合与映射表，并迁移显示关系。首版直接禁止人工结构拆分，允许文字段内换行。

## 4. 三路合并定义

定义 B 为编辑所依据的机器文本，U 为包含人工修改的文本，M 为最新机器文本。将 B→U 与 B→M 分别转成带稳定位置的差异。两组差异作用于相互独立的范围时，结果同时保留人工修改与机器新增。相同改动去重；重叠或定位存在歧义时转入待核对。

典型情形：

```text
B: According to Talmey, Path is encoded
U: According to Talmy, Path is encoded
M: According to Talmey, Path is encoded in the verb.
结果: According to Talmy, Path is encoded in the verb.
```

同一位置发生不同修改：

```text
B: The effect is fifteen percent.
U: The effect is fifty percent.
M: The effect is sixteen percent.
当前展示: The effect is fifty percent.
待核对机器版本: The effect is sixteen percent.
```

发生冲突时保留完整 U、最近一次安全展示与完整 M，包括机器可能增加的后半句。当前展示沿用最近一次安全展示，已经接入的续文继续可见。界面显示“含识别更新，待核对”，新内容不会被删除或伪装成已经合并。

## 5. 保守自动合并

自动合并必须同时满足范围互不重叠、插入边界可确定、重复短语不存在定位歧义和对应机器版本有效。相邻边界的插入与替换按保守策略交由用户核对。中文、英文和混合文本使用与编辑器一致的字符范围单位；生产实现优先采用 grapheme 边界与稳定文本映射。

本包的 Python 样例使用词项、空白和标点序列执行结构性差异合并，重复替换片段会触发保守回退。它验证状态语义与可恢复性；一般语言意义上的等价、复杂 Unicode 光标行为和完整编辑器映射需要生产实现与专门测试。

## 6. 打开编辑

`BeginEdit(segment_id)` 在单写者事务中读取机器版本、当前展示、当前人工修订序号和未解决冲突。

首次人工编辑采用当前机器文本作为基准。再次编辑时继承已有人工修改范围与其基准，并为新增用户动作记录独立差异；原有人工保护持续存在。本包参考程序采取更保守的累计文本方案，沿用原人工基准，因此某些机器变化可能产生更多待核对项。编辑会话存储 `editor_id`、`base_machine_text`、`base_machine_revision`、`snapshot_display_text`、`expected_user_seq` 和草稿。

编辑中的右侧原块可以固定在打开时快照，以防视觉漂移；后台展示投影仍正常计算。机器版本更新不改变左侧输入内容，也不改变人工修订序号。

## 7. 保存与确认

`CommitEdit` 携带 `command_id`、`editor_id`、`expected_user_seq` 与草稿文本。按以下顺序处理：

1. 查询命令幂等记录，已完成命令直接返回原结果。
2. 检查编辑会话有效、人工序号一致；并发人工改动造成不一致时保留草稿并返回冲突。
3. 创建不可变人工修订，记录编辑基准和新文本；没有文字改动则执行无修改关闭。
4. 对最新机器版本计算展示与候选状态，保存草稿结束记录和操作日志。
5. 提交 SQLite 事务，再发出 `CorrectionCommitted`。前端收到确认后显示“已保存”。

前端等待期间可显示乐观预览，但状态必须标为“正在保存”。超时后使用同一个 `command_id` 重试；命令语义保持一次生效。

## 8. 后续机器更新

机器事件携带 worker epoch、segment ID、hypothesis revision 和完整文本快照。仅接收当前 worker epoch；版本号必须递增；最终结果状态单调前进。旧任务、重复快照和晚到的临时结果分别记录为已忽略。

最终结果提交后，该块的同一次识别运行停止自动修订。课后重新识别使用独立 `reprocess_job_id`，输出候选版本，由用户选择应用；这也适用于更大模型生成的文本。

对已经有人工作业的块，任何机器更新都经过三路合并。保留最近原始机器文本、全部已确认人工历史、最近安全展示与当前候选状态。

**人工保护由明确的用户动作和受保护范围定义。** 模型后来恰好输出同一个修订词时，原有保护继续存在；禁止仅因当前机器文本与人工文本相同就清空修改记录。生产实现保存 protected edits 与来源锚点，重复编辑也继承这些保护。参考程序持续使用原始人工基准检验后续机器版本。

## 9. 撤销、重做与再编辑

人工动作进入独立撤销栈，自动增加的转写和临时识别快照从该栈排除。撤销修订恢复上一个人工版本，并使用最新机器文本重新计算展示，已经到达的后续课程内容继续保留。

人工序号单调递增，即使撤销也增加序号，用于使旧编辑会话失效。提交新的人工动作清空相关重做分支，历史仍保留用于审计。

本包参考程序实现修订撤销及清除当前覆盖的显式动作；重做、跨资料块的文档撤销和多窗口同步列在生产待办中。

## 10. 待核对动作的事务

“保留当前文字”以最新机器文本为基准重新创建修订。“采用此识别版本”清除当前人工覆盖，同时保留历史。两项动作均携带机器版本与人工序号的预期值，比较页面打开后发生变化时要求刷新比较状态。

用户逐项编辑合并的结果按正常人工修订保存。冲突状态不允许通过自动定时任务清除。

## 11. 资料、时间戳与删除

图片与公式使用 `anchor_segment_id` 和音频采样位置，而非当前段落序号。文字变化、视觉换行和机器补句均保持锚点不变。

首版逐块回放使用块级音频范围。修订后的文字可能与原音频用词不同，逐词时间戳设为 stale，后续对齐结果必须带新的文本哈希与对齐版本。用户资料不参与音频时间戳生成。

用户隐藏转写块时写 tombstone；音频与资料锚点保留，提供恢复入口。物理删除整个课程属于独立操作，需要明确确认和撤销或回收期策略。

## 12. 必测反例

编辑首词时机器添加后半句；机器改动同一个数字；重复出现同一个术语；中文输入法仍在组合；左侧草稿尚未提交时旧结果迟到；保存成功通知丢失后用户重试；应用在保存事务期间退出；停止录音时还有最终结果；用户在旧块加图片后列表重新分段；不同任务重用序号；撤销人工修订时后续文本已经到达。每种情形都有明确的预期状态，见测试矩阵和参考测试。
