# 06 · 录音管线与时间轴

## 1. 时间的定义

音频定位使用整数采样位置，单条标准识别轨道设为 16,000 Hz、单声道、16-bit PCM。课程墙钟时间与音频位置分别存储；暂停、设备断开、系统休眠会产生不同采集运行或缺口事件。

每个 `capture_run_id` 内的采样位置从零递增，课程时间由运行起点和间隔映射。机器事件和资料锚点必须同时携带运行 ID 与采样位置。系统时钟被调整时，音频位置保持稳定，显示时间依据单调时钟与持久化映射生成。

标准录音保存的是经过重采样的课程音轨。48 kHz 原始多轨存档可以后续增加，文件界面说明实际保存格式。

## 2. 采集与落盘

```text
设备帧 → 时间标记 → 有界回调队列 → 重采样 → 顺序音频存档
                                           └→ VAD / 推理候选范围
```

建议音频回调粒度约 20 毫秒；真实硬件回调长度可能不同，由累积缓冲器适配。音频回调不执行模型、数据库、图像或网络工作。写盘队列拥有更高处理优先级，推理消费音频索引与磁盘范围。

建议以 10 秒为一个 PCM 文件，写入期间使用 `.part`。约每秒请求一次文件持久化，完成后执行 flush、fsync、原子重命名及可用平台上的目录持久化，再提交块索引。音频文件和数据库采用恢复协议协调，两者的原子性分别保证。

两小时标准音轨的 PCM 数据约为 230.4 MB，按 16,000 × 2 × 7,200 字节计算；容器信息、索引、图片和备份另计。该值用于存储提示，实际占用从磁盘统计。

## 3. 崩溃恢复

恢复服务先扫描数据库与音频目录。完成文件存在而索引缺失时，读取旁侧元数据并补建索引；索引存在而文件缺失时记录缺口并警告。`.part` 文件按完整采样帧长度截断到最后可读边界，保留可恢复内容，重建元数据。

PCM 文件不依赖未完成的 WAV 长度头；导出时流式生成合法 WAV 或分卷。异常退出后的尾部保留程度由系统持久化行为决定，目标是在规定测试中将已接收但未持久化尾部控制在约一秒；物理断电、设备与文件系统故障需要分别测试并准确披露。

录音回调队列溢出时写缺口记录，显示录音质量警报。任何缺失音频都保留准确时间范围，禁止用合成静音掩盖错误状态；导出可用静音占位，但必须附缺口清单。

## 4. VAD 与分块初始策略

建议初始参数为约 200 毫秒前置上下文、450 至 600 毫秒尾部静音和约 12 秒的最大转写块。参数通过 G0 音频集调优。短停顿结束一个块，长讲话在上限附近选择能量较低的边界。

同一个块的音频所有权区间在时间轴上连续且不与邻块重复。前置上下文受到上一块结束位置约束。跨块重叠上下文需要独立标记，只有后端能可靠映射输出到所有权区间时才启用自动去重。

首版宁可在块边界给出待核对提示，也要保留真实重复话语。禁止按字符串公共前后缀直接删除相邻块中的重复句。

## 5. 有界窗口推理

首个块积累约 2 秒音频后允许发送快照；随后最多每约 2 秒提交一次增长后的窗口，且同一块只有一个活跃请求。语音结束或达到长度上限后生成必须处理的 final 任务。两秒是测试起点，并非实测延迟承诺。

重复提交 2、4、6、8、10、12 秒前缀会重复计算较多音频。实际调度根据上一请求耗时调整频率，取消尚未执行的旧 partial 请求并保留最新请求。可减频率、缩短块、切换小模型或进入稍后转写模式。

模型的 SSE token 可聚合为每约 100 毫秒一次的临时全文快照；前端渲染批次与模型 token 速率分离。完整文本最终确认后写入 final 状态。

## 6. 队列与背压

队列分为可替换的 partial 任务和持久化的 final 任务。partial 任务按 segment ID 合并，final 任务按音频时间顺序完成。录音存档持续写入，模型速度不足时积压保存在可恢复的任务索引中。

积压计算采用最新持久化音频位置与已经覆盖的最终识别位置，跨静音与缺口使用范围覆盖表。界面显示待处理音频时长；不能以“已生成字数”估计进度。

正常档位的初始目标是整场有效 RTF 不高于 0.7，给峰值与界面留出余量。该比值包含重复窗口计算。超过预警值时减少 partial 频率；持续积压时明确建议切换档位。自动调节只改变实时预览频率，已保存的音频与最终任务持续保留。

## 7. 系统声音与回授

macOS ScreenCaptureKit 支持应用级音频过滤。Apple 的说明指出，选择某个应用窗口时，该应用其他窗口的声音也可能属于采集范围，因此产品避免承诺浏览器标签页隔离。[S18] 本应用回放输出在平台能力允许时排除。

Windows WASAPI loopback 捕获输出端点的音频，存在共享模式与受保护内容等条件。[S19] 基线实现是输出设备级捕获。应用级隔离作为独立功能验证。

系统录音期间，本应用的回放也可能进入采集。耳机主要处理声学回授，系统 loopback 的自录仍需输出排除机制。未完成可靠排除的版本，系统录音期间禁用回放并解释原因。

## 8. 设备变化与系统状态

设备断开时停止该采集运行，记录原因，保存当前文件，显示“录音源已断开”。重新连接或切换设备由用户确认，并建立新运行。采样率或默认输出端点变化需要重建对应转换器，保留旧运行映射。

系统休眠与合盖期间可能无法采集；恢复后提示缺口并提供继续录音。应用可在录音期间请求合适的防空闲休眠行为，同时保留用户主动休眠和电量限制。低电量、内存压力和磁盘空间不足分别有可见状态。

磁盘空间不足时优先停止采集、完成尽可能多的持久化并记录故障。可预留一小块恢复空间供关键元数据写入；这属于辅助措施，不能保证故障文件系统始终可写。

## 9. 停止流程

停止录音操作先停止设备产生新帧，再排空采集队列、完成尾部文件、写关闭事件、生成最后的 final 任务。此时录音状态为 stopped，推理可以为 catching_up。

用户退出时允许“保存当前结果并下次继续处理”。恢复后从持久化任务与范围覆盖表继续处理，旧 worker epoch 的结果一律作废。停止按钮在重复点击时保持幂等。
