# 07 · 数据持久化与恢复

## 1. 目录布局

```text
<系统应用数据目录>/LectureEdit/
  database/main.sqlite3
  courses/<session_id>/
    audio/<capture_run_id>/<chunk_id>.pcm
    audio/<capture_run_id>/<chunk_id>.json
    assets/<sha256>.<safe-extension>
  models/<manifest_id>/
  backups/
  logs/                         默认仅操作元数据
  recovery/
```

Windows 使用用户应用数据目录，macOS 使用用户 Application Support 路径，通过 Tauri 的路径 API 获取。用户可在后续版本选择课程存储目录；活动数据库保持本地磁盘路径，云同步盘适合作为关闭后的导出或备份目的地。

## 2. SQLite 策略

启用外键、WAL、适当的 busy timeout 和 `synchronous=FULL`。单一领域写者串行处理事务，读取使用独立连接。WAL 提供读写并行特性，其写入与备份规则需按官方文档执行。[S20]

课程列表和文档视图使用增量查询。长时间备份、全文检索和导出不持有阻塞写入的应用级锁。数据库与文件目录定期执行完整性和引用检查。

## 3. 主表

`contracts/schema.sql` 提供可执行的初始数据库结构。重要对象如下。

| 对象 | 关键关系与约束 |
|---|---|
| sessions | 课程名称、创建时间、用户选择的语言、生命周期 |
| capture_runs | 同一课程中的设备、来源、采样率、起止映射与状态 |
| audio_chunks | 运行 ID、采样范围、相对路径、字节量、状态与校验值 |
| gaps | 缺失音频或设备变化时间范围与原因 |
| segments | 稳定 ID、采集运行、音频范围、机器状态、人工序号 |
| machine_hypotheses | 每块机器快照、版本、worker epoch、终态标记 |
| user_revisions | 基准机器文本与版本、人工全文、父修订、来源动作 |
| drafts | 一个编辑会话的快照、基准、人工序号、未提交文本 |
| note_blocks | 资料类型、内容 JSON、锚点、排序、修订与隐藏标记 |
| assets | 内容哈希、相对路径、MIME、尺寸和字节数 |
| note_asset_links | 图片资料到已保存附件的引用 |
| operations | 幂等命令 ID、课程级操作序号、确认响应 |
| jobs | 待处理音频范围、适配器、任务状态与重试次数 |

初始表包含必要的外键和范围检查。跨表同课程约束、当前修订指针和最终状态单调性同时由领域逻辑验证，避免误将基础 DDL 当作全部业务规则。

## 4. 保存事务边界

人工修订、人工序号、草稿完成状态、幂等命令记录和提交结果放进同一个 SQLite 事务。事务成功后发事件。用户可见确认与数据库确认一致。

音频文件先完成其持久化流程，再提交索引。图片先写入临时文件、校验与持久化，再以内容哈希原子命名，最后写附件记录及资料引用。应用崩溃造成孤立文件时由恢复服务识别，保留一定恢复期后清理。

临时识别快照可以合并写入以减轻 IO；用户打开编辑时，涉及的机器基准必须持久化或直接存入修订记录。最终机器结果与待核对候选按正常事务保存。

## 5. 事件同步与幂等

每条已提交领域事件具有课程内递增 `operation_seq`。前端订阅后获取一致快照及其序号，再接收更高序号事件。断线恢复可按序号补取；超出缓存范围时重新获取快照。

`command_id` 全局唯一，重复命令返回首次确认响应。用户序号用于人工修改的乐观并发检查；机器 revision 与 worker epoch 用于识别输出的顺序检查。三种版本号各自负责一种问题。

## 6. 草稿恢复

草稿持久化包含打开时的显示文本与机器基准，使再次启动后仍可完成同样的合并。输入自动保存有短暂防抖窗口，窗口关闭和对象切换尽可能立即持久化。界面使用真实的草稿保存状态。

崩溃后可恢复已持久化草稿；尚处防抖窗口的键入可能缺失。自动草稿和已确认修订分别说明恢复保证，避免将未确认输入计入“零丢失”承诺。

## 7. 备份与课程包

使用 SQLite backup API 或同等一致性机制创建快照，确保 WAL 中的已提交数据被包含。音频与附件采用不可变文件引用，备份清单记录内容哈希和快照操作序号。新写入文件由下一份备份处理。

课程包采用有版本号的 ZIP 容器：`manifest.json`、`document.json`、`audio/`、`assets/`、`provenance.json`。导入时检查路径穿越、重复路径、总展开体积、文件数量和哈希。包格式保留原始机器版本、当前人工修订与资料锚点；用户可选择精简导出以排除完整历史。

## 8. 删除与隐私

单块隐藏采用 tombstone，并提供恢复操作。课程删除移入应用回收区或由用户显式永久删除。删除内容包括数据库记录、音频、资料和对应备份范围，界面说明外部导出文件需要用户自行管理。

离线保存仍依赖操作系统账户与磁盘安全。首版利用系统权限保护文件，建议用户启用系统磁盘加密。应用内端到端加密或独立课程密码需要专门威胁建模与密钥恢复设计，安排后续版本。

## 9. 迁移与故障演练

每次数据库迁移带版本、摘要和验证查询。测试从每个已发布版本升级，检查记录数量、外键、修订与资料锚点。测试场景包括迁移前空间不足、迁移中强退、WAL 恢复、音频文件缺失、图片损坏和只读目录。

重建展示缓存与搜索索引时，原始音频和修订历史保持完整。恢复结果分为“已恢复”“部分恢复，存在明确缺口”和“需要手工处理”，每种结果包含可操作说明。
