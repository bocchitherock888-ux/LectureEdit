# 11 · 测试验收与性能计划

## 1. 验收级别

P0 代表数据安全、隐私或核心工作中断；P1 代表主要课堂流程不可用；P2 代表可绕过的体验问题。发布前 P0 和 P1 问题全部解决。真实语音与平台功能需要在对应系统上验收，参考逻辑测试只证明其覆盖的规则。

## 2. 核心行为矩阵

| 编号 | 测试情形 | 必须结果 | 级别 |
|---|---|---|---|
| E01 | 打开旧块编辑时新音频持续输入 | 录音采样数和新块均继续增加 | P0 |
| E02 | 用户改首词，模型补后半句 | 安全合并时保留两项变化 | P0 |
| E03 | 用户与模型修改同一数字 | 用户文本展示，完整机器候选保留 | P0 |
| E04 | 相同术语在段中重复 | 定位歧义进入待核对 | P0 |
| E05 | 临时结果在 final 之后到达 | 最终状态与展示保持有效 | P0 |
| E06 | worker 重启后旧响应到达 | 旧 epoch 响应丢弃 | P0 |
| E07 | 提交确认丢失后重试 | 同一命令只产生一次修订 | P0 |
| E08 | 保存草稿后强退重开 | 恢复已持久化草稿及基准 | P0 |
| E09 | 另一个编辑会话已提交 | 旧会话保留草稿并报告人工版本冲突 | P0 |
| E10 | 撤销修订时后续文本已出现 | 只撤销人工动作，后续文本继续保留 | P0 |
| E11 | 保存事务中断 | 完整旧版本或完整新版本可恢复 | P0 |
| E12 | 图片插入旧块后持续追加 | 图片锚点保持原块与时间 | P1 |
| E13 | 中文输入法组合期间按快捷键 | 候选输入行为正确，避免意外提交 | P1 |
| E14 | 旧内容阅读时新块到达 | 保持阅读锚点并显示新内容计数 | P1 |
| E15 | 编辑未改文字直接关闭 | 结束编辑并保留最新可用展示 | P1 |
| E16 | 课后大模型生成不同结果 | 产生候选，保留人工历史与当前修订 | P0 |

## 3. 录音与故障矩阵

测试麦克风授权拒绝与撤回、系统声音权限、静音、设备断开、采样率改变、输出设备切换、录音中回放、系统休眠、低电量、磁盘已满、只读目录、推理崩溃和应用强退。

每种故障检查三件事：已写音频与已确认修订是否可恢复，界面是否说明具体状态，以及恢复后音频时间映射是否准确。保存成功后的人工修订丢失为发布阻断项。音频尾部持久化目标在进程崩溃与断电测试中分别报告。

录音回调队列与磁盘队列需要压力测试，模拟推理占满 CPU/GPU、窗口缩放、导入大图片和导出长课程。任何丢帧都进入缺口表并被用户看见。

## 4. 性能目标，全部待实测

| 指标 | 初始目标 | 测量口径 |
|---|---|---|
| 编辑区打开 | p95 ≤120 ms | 已加载课程，点击到可输入 |
| 键入反馈 | p95 ≤50 ms | 真实输入到绘制 |
| 首次可见转写 | p95 ≤3.5 s | 首段有效声音到文本显示 |
| 语段最终结果 | p95 ≤6 s | 语音块结束到 final |
| 连续有效 RTF | ≤0.7 | 包含重复窗口计算的推理总成本与墙钟行为 |
| 连续课程 | 120 min | 无持续增长的识别积压，异常需说明 |
| 人工文字覆盖 | 0 次 | 自动处理无授权覆盖用户修订 |
| 已确认修订丢失 | 0 次 | 故障测试中数据库确认后的版本 |
| 屏幕动画 | 参考设备上尽量稳定 60 fps | 实际显示器与系统帧数据 |

内存、CPU/GPU 和能耗先测量再定档。报告同时给均值、p50、p95、最大值和原始样本数，避免用一次最好结果描述体验。内存常驻与加载峰值分别记录。

## 5. 真实音频集

由用户或团队提供有处理权限的录音，人工校对一部分作为参照。英语测试覆盖清晰讲授、学术术语、英美及其他口音、数字和快速连续语音；中文测试覆盖普通话、术语与英文插入；噪声测试覆盖远场、风扇、键盘、静音与背景音乐。

每个样本记录语言、来源、时长、质量条件和授权状态。模型识别输出可帮助标注员校对，最终参照以人工核对音频为准。参考真值、开发集和最终验收集分开。

## 6. 硬件测试表

至少包含一台 Apple Silicon MacBook Air 和一台 Windows 11 x64 普通轻薄本。记录准确芯片、内存、系统、加速后端、电源状态和温度条件。若要宣称支持 8 GB，则加入真实 8 GB 机器；若要提供 NVIDIA 加速，则另外测试对应显卡。

Mac 和 Windows 上各测试清洁安装、模型首次下载、断网启动、长录音、修改、资料插入、导出、异常恢复与卸载。Intel Mac 和 Windows ARM 在独立通过后进入支持清单。

## 7. 自动化测试结构

领域单元测试覆盖合并、版本顺序、撤销、资料锚点和幂等。SQLite 集成测试覆盖事务、外键、迁移、草稿与恢复。模拟音频与模型事件用于 UI E2E；真实模型用于适配器集成测试。平台捕获、权限和回授使用原生人工或自动化测试。

随机测试生成互不重叠与重叠修改，检验用户变更保留、冲突候选完整和幂等性。并发压力测试注入乱序、重试、延迟与崩溃点。渲染测试覆盖不同窗口尺寸、文字大小、减少动态和高对比度。

## 8. 当前交付的验证边界

`tests` 运行的是 Python 参考领域规则、SQLite 初始结构和资源质量检查。它不执行实际麦克风、系统声音、Rust、Tauri、模型推理、输入法或 GPU 路径。当前测试结果见根目录 `TEST_REPORT.md`；生产验收结果使用 `implementation/benchmarks.template.json` 和独立测试报告记录。
