# 01 · 产品定义与版本边界

## 1. 用户要完成的事情

用户在听课时同时录音、阅读转写、修正刚刚听到的专有名词，并将公式、课件截图、例子和自己的理解附到当时的内容上。课程结束时，用户得到一份保留音频来源、修订记录和课堂资料的可编辑笔记。

产品的核心价值是降低“发现错误”和“完成修订”之间的时间距离，同时保留后续课堂内容。第一优先级是持续可靠录音，第二优先级是人工文字的安全，第三优先级是实时性，随后是识别精度提升、排版和动效。

## 2. 已核实的差异与研究边界

Otter 的官方帮助说明，转写文本修改需要等录音结束并处理完成；实时阶段可进行评论、标注和图片操作。[S08] Notion 的 AI meeting notes 帮助说明当前录音转写依赖联网。[S09] 这两条资料分别支持实时修订与离线工作的产品方向。此次调研未进行全市场功能普查，也未实际操作这些产品，因此商业定位应采用可核查的具体对比。

可对外描述的定位为：**一边录音、一边修订、原位整理资料的本地课堂转写工具。** 避免在宣传中使用“全球首个”或“所有现有产品都做不到”等无法验证的表述。

## 3. 首批用户与输入环境

首批用户是使用笔记本上课的大学生、研究生和参加专业培训的工作者。优先场景包括实体课堂的麦克风录音、线上课程的系统声音、英文讲授、中文补充和学术术语。远距离教师声音、教室回声、口音和中英切换属于必须纳入实测的数据条件。

应用可以显示中文界面或英文界面；识别语言设置与界面语言分开。首轮质量验收以英语和普通话为重点，其他受模型支持的语言标为扩展能力，按独立测试结果描述质量。

## 4. 成功的一次课堂使用

用户提前下载模型并完成一次设备检查。上课时选择音频来源，点击开始。转写块逐步出现；看到错误后点该块的“取出编辑”，左侧出现稳定编辑区。右侧新增内容继续出现。用户修改单词，按 Cmd 或 Ctrl 加 Enter 提交，修订立即回到原来的音频位置。模型后来更改同一句时，系统保留用户修改，并将无法安全合并的版本放入待核对区。

需要公式、例子或图片时，用户在指定段落下添加资料卡。录音结束后，应用继续处理剩余音频，用户可以继续编辑和导出已完成的内容。界面同时显示“录音已结束”和“尚余多少音频待处理”。

## 5. 版本范围

| 阶段 | 交付范围 | 明确的出口条件 |
|---|---|---|
| G0 可行性验证 | 两个系统的原生推理、麦克风与系统声音验证，模型清单与性能记录 | 两个系统均有可重复结果，选择默认后端 |
| v0.1 内部试用 | 麦克风录音、本地转写、取出编辑、冲突保留、草稿恢复、基本导出 | 连续课程录音与人工修订安全测试通过 |
| v0.2 双平台课堂版 | 系统声音、资料块、图片、公式、回放、完整课程导出 | 两个系统完成端到端课堂测试 |
| v1.0 发布候选 | 安装与更新、签名、权限引导、无障碍、性能与故障验收 | 发布清单中全部 P0 和 P1 问题关闭 |

首个公开版本覆盖 Windows 和 macOS。建议支持基线为 Windows 11 x64 与 macOS 14 或以上的 Apple Silicon；这是开发范围建议，需在 G0 确认原生依赖与用户设备。Intel Mac 列为兼容性扩展项，Windows ARM 列为后续目标。界面、数据库和编辑语义保持一致，录音权限、系统声音与安装流程分别实现。

## 6. 延后功能

多人同步、云端账户体系、说话人聚类、实时翻译、课程问答、自动生成总结、双音源同步混音和全文强制对齐安排在核心版稳定以后。API 接入先保留完整协议与显式授权入口，v1.0 可只实现本地后端；开发团队应在项目开始时选定是否增加一个云端适配器。

避免将第一版扩展成完整知识库。课程列表、课堂文档与复习检索足以支撑初始使用。

## 7. 产品不变量

1. 编辑动作与录音动作各自独立。
2. 系统确认保存后的修订具有可恢复的持久化记录。
3. 人工修订和人工资料始终保留来源，自动处理只能生成安全投影或待核对候选。
4. 每条转写、修订与资料都可追溯到稳定标识和音频时间范围。
5. 本地模式完成模型安装后可以断网工作，后端故障只能触发本地恢复或用户明确选择的其他方案。

## 8. 课堂可用性验证

内部试用安排 5 至 8 位实际听课用户完成同一组任务：修正一个术语、在旧段落插入公式、查看新内容、找到修订过的音频位置。记录每项任务耗时、误触录音暂停次数、误提交次数和忘记返回听课的情况。单词修订从打开到保存的初始目标为十秒内，实际结果由试用记录决定。
